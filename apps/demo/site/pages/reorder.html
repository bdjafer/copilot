List reorder

A comment belongs to the item, not to li:nth-child(3).
  1. Comment on Kiwi (the third row).
  2. Press Shuffle or Sort A→Z. The badge follows Kiwi.
  3. Press Remove Kiwi. The thread orphans and its badge docks to the corner.
  4. Press Restore. It re-anchors — watch thread:anchored in the log.
Rows deliberately have no id: position and CSS path are both worthless here, so the match has to come from the fingerprint and the row's own text.

Why the demo raises anchoring.threshold to 0.9 (in assets/demo.js, for every page). After a shuffle the stored CSS selector #list > li:nth-of-type(3) still matches — it now points at whoever moved into that slot. That wrong row scores ≈0.76: tag, classes, depth and shape all still match, and only the text differs, which is worth 0.12 of the total weight. The library's default accept score is 0.62, so the resolver takes it and never runs the fingerprint scan that would have found the row at its new position (score 1.00). Raising the accept score is the documented knob; whether the default itself should move is a question for the M2 anchoring bench against real sites (PLAN §3.8).
