Attribute churn

Build-hashed class names (css-1x9f3q), regenerated React ids (:r7:) and framework bookkeeping attributes change on every deploy — and sometimes on every render. This page churns them under live anchors, in two steps, because the two behave very differently today.
  1. Comment on a paragraph below.
  2. Churn hashed classes — the paragraphs are re-created with new css-… / sc-… class names. The badge does not move, and deterministically so: a class becomes evidence only when it is word-like and carried by a second element (SPEC §2.5, decision log #28), so a per-render random name — unique in the document by construction — never reaches the fingerprint. Confidence stays at 1.00. Before that rule it was a coin flip: css-<hash> passes the word-like test about one render in seventeen.
  3. Churn ids and data attributes too — the framework-hydration case. id is worth 0.2 of the score and the data-*/aria-* set another 0.3, but a value that was rewritten and now matches nothing anywhere in the document carries no information — it cannot mean "not this element" (decision log #27). The thread re-anchors, flagged approximate: the text still verifies, the confidence honestly drops to ≈0.75, and the badge shows the "approximately re-anchored" marker. Rewrite the text as well and it orphans instead.
  4. Rewrite the text too is the other honest degradation: change what an element says and the match falls below the accept score rather than pointing at the wrong thing.
