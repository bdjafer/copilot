Popover open/close — the canonical orphan case

This is the scenario the whole anchoring design exists for. A Radix/shadcn popover unmounts its content when it closes: the element a thread points at stops existing, then a structurally identical one appears somewhere else in the DOM later.
  1. Open the popover, comment on a row inside it.
  2. Close it. thread:orphaned fires, the badge docks to the panel corner, and nothing is written to the store — an orphan is a live derivation, not a state change.
  3. Open it again. thread:anchored fires and the badge snaps back.
The second popover mounts into a portal at the end of <body>, so its DOM path changes between opens. That is the case a CSS selector alone cannot survive.
