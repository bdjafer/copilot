Comment on a page nobody built for commenting.

Anchors are scored, not looked up. Every page below is static HTML served off disk — no extension, no service worker, no bundler, no model. Threads live in localStorage, keyed by page URL, and the “copilot” is an echo responder: a setTimeout and one call to engine.appendComment({ author: 'copilot' }).

Nothing exists until you ask for it. A resting badge is a 12 px dot at 72 % opacity; bring the cursor within 96 px, tab to it, or give it something to say, and it becomes a pill. The corner panel is zero pixels until the page has its first thread. That is the whole difference between an annotation layer and a tool that vandalises somebody's page with twelve permanent blue pills — and it only holds up because five mitigations ship together: touch, keyboard focus, a live copilot chip, the two seconds after a page change, and a complete accessible name in every state, including the dot.

The scenario matrix

  • Basic static page

    The baseline: place, reload, the badge comes back on the same element.

  • List reorder

    Rows shuffle, sort, disappear and return. The badge follows the row, not the slot.

  • Popover open/close

    The canonical orphan case: content unmounts, the badge docks, reopening re-anchors it — with no write to the store.

  • Infinite scroll

    Late-arriving nodes, trimmed feeds, and badges that hide themselves off-screen.

  • SPA route change

    One document, several page keys, an injected navigation.source, and a working Back button.

  • Attribute churn

    Hashed classes and regenerated ids are rewritten underneath live anchors.

The appearance

  • The material

    One page about one thing: what the overlay is made of, and what a 3D renderer would have cost to say it. Includes the byte ledger that deleted the shader.

Every page mounts glassPresentation() by default — ?theme=default switches any of them back to the frozen original in one reload, which is the cheapest possible proof that the renderer really did split into a headless controller and a swappable presentation.

What to look at

Each page has a toolbar with a live event log. thread:anchored prints the strategy that won and its confidence; thread:orphaned prints when an anchor stops resolving. Those two lines are the entire anchoring story.

The echo line — echo → 1a2b3c · reopened=false deduped=false — is the domain story: a copilot reply never reopens a resolved thread, and it carries an idempotency key so a reload mid-flight cannot double-post.
